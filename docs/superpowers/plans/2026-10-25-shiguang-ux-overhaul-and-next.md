6. 偏好文件被占用时写失败却报成功 → 必须真替换成功，重试 5 次仍失败如实报错。
7. 调色板/1-bit 图缩略图锯齿 → 这两种模式先转色再缩。
8. 插卡后增量同步(逐张读 EXIF)期间没反馈 → 先刷新/弹窗("正在检查卡上新拍的照片…")，同步完再刷新+提示+更新小窗。

### 评分 v3 依据(调研摘要，出处在调研报告里)
- 各家"剪切警告"都是显示用阈值：RawTherapee 高光=任一通道≥253、阴影=三通道≤8；darktable `rawoverexposed` 按 CFA 逐通道与(白点−黑电平)比；FastRawViewer：过曝=RAW 通道饱和，欠曝=低于饱和 8EV(高 ISO 6~7EV)。相机直方图/高光警告基于 JPEG，会报 RAW 里没发生的剪切。
- 本软件：RAW 可信时 高光修剪=四通道都≥饱和电平 98%(成片)、部分通道饱和单列(可部分恢复)、阴影修剪=四通道都低于饱和 8EV(ISO≥3200 用 6.5EV)；饱和电平取标称白电平与数据饱和平台的较小者。
- 噪点：传感器噪声为泊松-高斯，拟合 σ²=aμ+b(Gr−Gb 双绿差分 + 块内 MAD，抗纹理)，报 SNR18(DxOMark 口径)与画面中间调信噪比。阈值锚点：ISO 12232 的 10:1=20 dB"可接受"；散粒噪声每档≈3 dB；AI 降噪宣称 2~3 档≈+6~9 dB → <11 dB 判"降噪也救不回"(推导值，待校准)，11~20 dB 扣分。
- 可信度：RAW 缩图与内嵌 JPEG 秩相关 <0.8(或解码失败)一律不用 RAW——LibRaw 0.22.2 的机型表无 Z50II、"高效率 NEF"只对 Z9/Z8/Zf/Z6III 开放，Z50II 的 HE 文件很可能解坏；此时退回预览估算，RAW 文件的预览高光硬阈放宽到 25%，噪点不判。
- 为省读卡时间，只对预览上有可疑迹象(到顶像素>0.3%、亮度中位数<55、ISO≥3200)的照片读 RAW。
- 未纳入、可选的维度(待用户拍板)：运动模糊/失焦区分(digiKam 式 Hough 线方向一致性)、按 EXIF 对焦点区域判清晰度、地平线歪斜提示、快门安全速度先验；不推荐：BRISQUE/NIQE(对浅景深误判、pyiqa 非商用许可)、美学评分(偏好不是硬伤)、闭眼(用户已定不做)。

## 二、后续大项（需单独排期）

### L1. 原生窗口外壳：自绘标题栏 + 系统原生动画（微信/QQ 的做法）
- 目标：保留现在的自绘标题栏，同时拿回 Windows 原生的最小化/最大化/还原动画、Aero Snap(拖到屏幕边缘分屏)、窗口阴影、Win11 圆角、拖边改大小、双击标题栏最大化。
- 做法：
  1. 窗口创建后取 HWND，补上 `WS_CAPTION|WS_THICKFRAME|WS_MINIMIZEBOX|WS_MAXIMIZEBOX|WS_SYSMENU`（动画和 Snap 都挂在这些样式上）。
  2. `SetWindowSubclass` 子类化窗口过程：`WM_NCCALCSIZE` 返回 0 把系统边框藏掉（最大化时按边框厚度内缩，防内容被裁）；`WM_GETMINMAXINFO` 修多显示器最大化尺寸。
  3. 拖动改原生：标题栏 mousedown → 后端在 GUI 线程 `ReleaseCapture + SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)`，由系统接管拖动（顺滑、支持 Snap/晃动最小化），替换 pywebview 现在"JS 每帧发坐标"的拖法。
  4. 拖边改大小：页面四周放几像素的透明热区，按下时同理发 `HTLEFT/HTRIGHT/...`（WebView2 子窗口盖住了客户区，父窗口收不到命中测试，所以从页面侧触发最稳）。
  5. `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE)` 圆角 + DWM 阴影。
  6. "缩到托盘"先播系统最小化动画再隐藏。
- 现状核实(读 pywebview 5.3 源码)：WebView2 控件 `Dock=Fill` 铺满无边框窗体(`FormBorderStyle.None`)，所以现在**窗口边缘根本不能拖拽改大小**；WinForms 无边框窗体最大化通常会**盖住任务栏**(需真机确认)——L1 的 `WM_GETMINMAXINFO` 按工作区限定最大化尺寸可一并修掉。
- 风险：上次只加 `WS_MINIMIZEBOX` 出现过"卡死的幽灵窗口"已回退；Python 窗口过程跑在 GUI 线程要抢 GIL，后台分析/预生成时可能拖慢拖动——只处理少数消息、其余立即交回系统。
- 验证：必须真机。计划用隔离的用户目录起第二个实例（需给单实例互斥锁加测试用开关），配合屏幕截帧检查动画；每一步都可回退。
- 工作量：约 1~2 天，多轮真机试。

### L2. 极速预览层（手机相册"划多快都不白"的关键）
- 手机的做法：拍照/导入时就生成一份很小的预览（几 KB），整个图库常驻，滑动时先显示小图再换清晰图。
- 本软件：RAW 里除了全尺寸预览，通常还有 160px 级的小缩略图，读文件头附近一小段即可取出，比生成 512 缩略图快一个数量级。插卡后先给全卡生成小预览（预计千张十几秒），网格先显示小图（轻微模糊），512 到了再换。
- 前置：需要真实 NEF 样片验证（当前图库 655 张 NEF 都在卡上、卡未插，样片不可用）。请把一张 NEF 放到 `tests/fixtures/sample.cr2`（见该目录 README），或测试时插卡。
- 工作量：约半天 + 样片验证。
- 更省事的替代(待用户拍板)：退出时**保留 256 小档缩略图**(每张约 15KB，655 张约 10MB)，只清 512/预览/原图。这样每次启动不用重新读卡生成缩略图，划多快都有图——手机相册就是这么做的。与"退出清缓存"的原决策冲突，需用户同意。
